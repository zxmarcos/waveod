# Translations (i18n)

The pedal's screens and waveod Studio show their texts in English (the default and the reference), Portuguese,
Spanish, German or Italian, from one catalog. Adding a language is adding its files and running one tool.

## The catalog

```
i18n/languages.json          the languages, in the order the pedal stores them (only ever append)
i18n/en/*.json               English: the reference and the fallback
i18n/pt-BR/*.json            Portuguese (Brazil)
i18n/es/*.json               Spanish
i18n/de/*.json               German
i18n/it/*.json               Italian
```

- `languages.json`: `{"code", "name", "pedal"}` per language. `name` is what the Studio shows; `pedal` is the
  pedal's name for it, in its upper case (GLOBAL › TELA › IDIOMA). The pedal keeps the language's index in its
  settings, so the order never changes: a new language goes at the end.
- Each language has the same files: flat JSON objects `{"key": "text"}`, one per area (`fw-common.json`,
  `fw-controls.json`, `studio-controls.json`...). A key lives in one file only.
- Keys are `fw.<area>.<name>` (the pedal), `studio.<area>.<name>` (the Studio: the page and its Python backend)
  or `shared.<area>.<name>` (texts both show alike: footswitch functions, curves, LED colours, scene names).
  Lower case, digits and `_`, dots between the parts.

## Writing texts

- **The pedal:**
  - Write the text as the screen shows it: most labels are upper case (`"LINK REMOVED"`), toasts and alerts are
    sentences.
  - Placeholders are printf's (`%d`, `%s`, `%+d`, `%.1f`), and every language has the same ones in the same order:
    `lv_snprintf` has no positional arguments.
  - Only the characters the pedal's fonts have: Latin-1 (U+0020-U+007E, U+00A0-U+00FF) plus `–` U+2013 and
    `−` U+2212. `check` reports any other; a language that needs more (Latin Extended) needs the fonts regenerated
    with its characters (`assets/fonts`, the ranges in each `src/ui/fonts/*.c` header).
  - Keep it as short as the English: the screen is 480 × 272 and many places truncate.
- **The Studio:** placeholders are `{name}`; a count has two keys, `<key>_one` and `<key>_other` (others like
  `_few` when a language's plural rules need them), read with `tn('<key>', n)`.
- **Not translated** (they stay as they are, in English): the names of effects, their parameters and their named
  values (they come from the effect libraries and the blocks' descriptors), units (Hz, dB, ms, BPM), product terms
  (MIDI, CC, PC, EXP, MOD, LFO when it is a name), preset and scene names the user wrote.

## In the code

- **Pedal (C):** `#include "ui/i18n.h"`, then `T(MSG_<KEY>)` for the text of `fw.<area>.<name>`
  (`MSG_<AREA>_<NAME>`) or `shared.<area>.<name>` (`MSG_SHARED_<AREA>_<NAME>`).
  - A table of texts (`static const char *const names[] = {...}`) becomes a table of ids
    (`static const uint16_t names[] = { MSG_X, ... }` read with `T(names[i])`).
  - A format: `lv_snprintf(out, size, T(MSG_X), a, b)`.
  - Code outside the UI (model, engine) may use T() too (the tests link the tables). It names a message the screen
    shows; the language is the setting's.
  - The language is `settings.language` (GLOBAL › TELA › IDIOMA, the editor protocol's setting 40). When it
    changes, `ui.c` builds every screen again, so texts set once in `create()` follow.
  - The generated `src/ui/i18n_msgs.c` keeps each language's texts in one array in SDRAM (`ui/sdram_code.h`), not
    as string literals: a literal would land in ITCM, which is kept for the audio path.
  - A label that may get a longer text in another language needs one line's height with `LV_LABEL_LONG_DOT`:
    without a fixed height LVGL wraps it instead of cutting it short.
- **Studio page (Svelte / TS):** `import { t, tn, num, decimal } from '../lib/i18n.svelte'`;
  `t('area.name', {params})` for `studio.area.name` (the `studio.` prefix is left out) and
  `t('shared.area.name')`. The keys are typed: one that does not exist fails `npm run check`.
  - A list of labels in a module becomes getters or functions (`get label() { return t(...) }`), so a page reading
    it follows the language.
  - Numbers: `num(v, decimals)` writes them as the language does (decimal comma in Portuguese); `decimal(text)`
    changes the point of a text that already has one.
- **Studio backend (Python):** `from waveod_studio.i18n import tr`, `tr('area.name', name=value)`. The page tells
  the backend its language (`Api.set_language`); the command line uses the system's.

## The tool

```
python tools/i18n.py gen              the tables from the catalog (commit them)
python tools/i18n.py check [--strict] [--unused]
python tools/i18n.py scan FILE...     the literals of a source file, to move into the catalog
```

`gen` writes `src/ui/i18n_msgs.h` / `.c` (the pedal), `studio/ui/src/lib/i18n/strings.ts` (the page) and
`studio/waveod_studio/i18n_strings.py` (the backend). `check` reports keys missing in a language (errors with
`--strict`), keys a language has and the reference does not, placeholders that differ, characters the pedal's
fonts lack, and generated files that are stale; `--unused` lists keys no source names.

## Adding a language

1. Append it to `i18n/languages.json` (`code` as BCP 47: `es`, `de`, `fr-CA`; `name` in the language itself;
   `pedal` in upper case).
2. Copy `i18n/en/` to `i18n/<code>/` and translate every file (keep the keys; a text left out shows in English).
3. `python tools/i18n.py gen` and `python tools/i18n.py check --strict`.
4. Build the firmware and the Studio page; check the screens in the simulator (`waveod-sim`, GLOBAL › TELA ›
   IDIOMA) and the page with `?lang=<code>` (`npm run dev`).
